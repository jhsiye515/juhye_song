## 하는 일

| 일 | 설명 | 산출물 |
| --- | --- | --- |
| 기능 정의 | 요구사항을 기능 단위로 쪼개고, 기능마다 화면 · 정책 · 권한 · 우선순위를 붙입니다 | 기능 정의서 |
| 정책 정의 | 숫자 · 조건 · 상태 전이처럼 바뀌기 쉬운 규칙을 한곳에 모읍니다. 기능과 화면은 정책 ID만 가리킵니다 | 정책 정의서 · 공통 정책 |
| 화면 설계 | 예시 데이터로 실제처럼 움직이는 화면을 만들고, 자리 번호마다 기능 · 정책 ID를 답니다 | 화면 목록 · 화면 설계서 |
| 품질 검사 | 테스트 케이스를 차수별로 돌리고, 결함 · 결정 필요 · 개선 제안을 나눠 기록합니다 | 테스트 결과 엑셀 |

## 소개

B2B 관리자 제품의 서비스 기획자입니다. 요구사항을 문서로 쪼개 개발 · QA와 같은 근거를 보고, 정해지지 않은 것은 결함과 따로 모아 담당과 추천안을 붙입니다. 문서가 실제로 동작하는지 확인하려고 화면까지 직접 만들어 봅니다.
