## 배경

기획 문서는 위키에, 화면 설계는 디자인 툴에, 품질 결과는 엑셀에 흩어져 있었습니다. 문서가 바뀌어도 다른 문서가 따라 바뀌었는지 알 수 없었고, 개발 · QA는 어느 것이 최신인지 매번 물어야 했습니다.

## 접근

- 기획 하나를 폴더 하나로 두고, 문서 넷(기능 정의서 · 정책 정의서 · 화면 목록 · 화면 설계서)과 품질 결과를 같은 폴더에 모았습니다.
- 문서끼리 ID로 잇는 규칙을 정하고, PR마다 ID 겹침 · 끊긴 참조를 검사하게 했습니다.
- 포털은 저장소를 읽기만 합니다. 고치는 곳은 늘 저장소 원본이고, 화면마다 원본으로 가는 버튼을 두었습니다.
- 홈에는 숫자보다 할 일을 먼저 두었습니다. 「기획이 할 일 · 개발이 할 일」로 나눠 누가 무엇을 해야 하는지 바로 보이게 했습니다.

## 결과

- main 에 머지하면 포털이 다시 만들어집니다. 포털에 보이는 것이 늘 main 의 확정본입니다.
- 기능 정의서 · 정책 정의서 · 화면 목록은 엑셀 · 워드 사본으로도 내려받을 수 있어, 저장소를 쓰지 않는 사람과도 같은 문서를 나눕니다.

## 포털에서 볼 수 있는 것

| 이름 | 설명 |
| --- | --- |
| 기획 | 기획별 단계(작성 중 · 검토 중 · 확정 · 품질 검사)와 문서 넷 |
| 결정할 것 | 미결정 · 결정 필요를 한곳에 모으고 담당 · 기한을 붙임 |
| 품질 | 차수별 통과율, 결함을 고칠 곳(기획 · 개발 · 디자인)으로 나눔 |
| 공통 정책 | 여러 기획이 따르는 규칙과 그 규칙을 쓰는 화면 |
