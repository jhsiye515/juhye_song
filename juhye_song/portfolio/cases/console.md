## 배경

운영팀은 알림이 오면 메신저로 담당을 정하고, 처리 결과는 엑셀에 따로 적고 있었습니다. 급한 건이 묻히고, 해결 목표 시간을 지켰는지 월말에야 알 수 있었습니다. 서버와 비용도 클라우드마다 다른 화면에서 봐야 했습니다.

## 접근

- 운영팀 요구사항을 기능 ID로 쪼개고, 기능마다 화면 ID와 정책 ID를 붙였습니다.
- 우선순위별 목표 시간 · 상태 전이 · 알림 묶기 같은 숫자와 조건은 정책 정의서에만 적었습니다. 값이 바뀌어도 한 곳만 고치면 됩니다.
- 날짜 표기 · 목록 표 · 상태 배지처럼 여러 화면이 함께 쓰는 규칙은 공통 정책으로 뺐습니다.
- 화면 설계서는 예시 데이터로 실제처럼 움직이게 만들고, 오른쪽 자리 번호 설명에 기능 · 정책 ID를 달았습니다.

## 결과

- 기획서의 기능 · 정책을 그대로 구현한 운영 콘솔을 함께 만들었습니다. 등록 · 담당 맡기 · 해결 · 종료, 권한, 알림 묶기, 목표 시간 계산이 실제로 동작하고, 「기획 ID 보기」를 켜면 화면마다 근거가 된 기능 · 정책 ID가 보입니다.

- 인시던트 처리 큐는 2차 품질 검사까지 진행했고, 1차에서 나온 중요 결함 2건이 2차에서 확인 완료됐습니다.
- 품질 검사에서 나온 정할 것은 결함과 따로 「결정 필요」로 모아 담당 부서와 추천안을 함께 적었습니다.

## 구현하며 찾은 기획의 빈틈

문서만 쓸 때는 보이지 않던 것을 화면을 만들면서 찾았습니다. 찾은 것은 화면에도 그대로 밝혔습니다.
