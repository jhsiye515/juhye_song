## 1. 원칙

- 사이트는 **OPS 포털 양식**으로 그린다. 포털 양식은 운영 포털 전용 디자인 시스템이다. 토큰 · 부품 · 쪽 패턴 · 글 규칙의 정본은 `tools/site/ds/portal.css` 한 장이다.
- 제품 화면용 제품 디자인 양식(`design/`)은 쓰지 않는다. 운영 포털이 제품처럼 보이면 어느 쪽이 제품인지 헷갈린다.
- 값을 바꾸면 포털 양식 아티팩트와 `portal.css` 를 같은 값으로 고친다. 한쪽만 고치면 다음 사람이 어느 값을 따를지 모른다.
- 모양은 노션 · 지라처럼 깔끔하게 둔다. 바탕은 모두 흰색이고, 상자와 색 띠 대신 얇은 선과 여백으로 나눈다. 문서 본문은 상자 없이 흰 바탕에 바로 쓴다. 색은 먹색 글자, 포인트 파랑 하나, 상태 셋(끝남 초록 · 손볼 것 주황 · 문제 빨강)만 쓴다. 맡는 곳(기획 · 개발)은 색 없이 회색 테두리 배지와 글자로 구분한다. 글자 크기는 여덟 단(32 · 28 · 22 · 18 · 16 · 15 · 14 · 13 · 12 가운데 본문 15, 문서 본문 16), 굵기는 400 · 500 · 600 셋이고 `portal.css` 토큰으로만 쓴다. 글꼴은 시스템 글꼴이다.
- 글자는 메인과 서브를 색과 크기로 나눈다. 메인(제목 · 본문 · 표 내용)은 먹색 15~16px, 서브(설명 · 위치 · 보조 줄 · 건수 · 표 머리)는 회색 13px다. 여백은 넉넉하게 둔다: 구획 사이 40px, 카드 안 24px, 표 칸 14px 16px.
- 회색은 푸른 기가 도는 중립 회색만 쓴다. 누런(따뜻한) 회색과 누런 바탕색을 쓰지 않는다. 손볼 것은 주황 글자, 미확정 구획과 찾아온 자리는 옅은 회청 바탕이다.
- 화면은 목적에 따라 틀이 다르다(4장). 보는 화면은 숫자와 할 일을 먼저 두고, 읽는 화면은 본문을 먼저 둔다.
- 읽기 전용이다. 고치는 곳은 늘 GitHub 원본이고, 화면은 원본(경로 · 엑셀)으로 가는 버튼을 둔다.
- 포털은 기획서 규칙이 아니라 사람들이 익숙한 일반적인 문서 사이트 관례를 따른다. 왼쪽 메뉴, 가운데 본문, 오른쪽 「이 페이지 목차」를 두고, 화면 용어도 검색 · 담당 · 참조처럼 흔히 쓰는 말을 쓴다.
- 화면 문구는 「명확한 한국어」 기준으로 쓴다. 할 일 문장은 상태가 아니라 할 일을 쓴다. 예: 「중요 이상 결함 5건을 고칩니다.」 (Claude 판단안 · 팀 확인 전)
- 지표 정의는 화면에 적는다. 통과율: 통과 ÷ (통과 + 실패). 실행: 통과 + 실패 (GD-09).

## 2. 전역 규칙

모든 화면에 같은 규칙을 쓴다. 화면 하나를 고칠 때도 이 표를 바꾸는 것이 먼저다. 이 표를 바꾸면 모든 화면을 같이 고친다.

| # | 대상 | 규칙 |
| --- | --- | --- |
| G1 | 쪽 순서 | 띠(위치 · 제목 · 정보 줄 · 설명 · 쪽 탭) 다음에 숫자 타일, 차트 카드, 표 순서로 둔다. 없는 칸은 빼고 순서는 바꾸지 않는다 |
| G2 | 설명 | 쪽 제목 아래 한두 문장. 이 쪽에서 무엇을 보는지와 값이 어디서 왔는지만 쓴다. 쓰는 법 안내는 쪽 맨 아래 `.help` 한 줄 |
| G3 | 요약 타일 | 한 쪽 4~5개. 이름은 「누가 · 무엇」(예: 개발이 고칠 결함), 숫자에 단위(건 · 개), 누르면 그 조건의 목록. 타일에는 색을 칠하지 않는다. 0이면 수를 흐리게(`.o`) |
| G4 | 차트 카드 | 카드 제목은 무엇을 보는지(「기획별 건수」) 또는 질문(「열린 결함은 어디서 고치나요?」). 본문 첫 줄은 답 한 문장, 그 아래 막대 · 범례. 차트만 두지 않는다 |
| G5 | 표 | 첫 칸 ID(고정폭 글꼴), 이름은 `.ttl` + 아래 `.sub` 한 줄, 숫자는 오른쪽 정렬 · 단위. 정렬은 「열린 것 → 심각도 → 우선순위 → ID」 |
| G6 | 한 건 보기 | 목록 안 한 건은 오른쪽 상세 패널(`.panel`), 따로 읽는 문서(기획 · 정책 · 운영 문서)는 상세 화면. 패널 맨 아래에 원본으로 가는 버튼 |
| G7 | 상태 배지 | 끝남 · 확정 `ok`, 손볼 것(신규 · 결정 필요 · 검토 중 · 샘플) `warn`, 개발 결함 `bad`, 종류 · 그 밖 기본(회색), 「최신」 같은 표시 `acc`. 이 밖의 색을 상태에 쓰지 않는다 |
| G8 | 맡는 곳 | 기획 · 개발은 회색 테두리 배지, 디자인은 회색 배지 + 문장 |
| G9 | 숫자 · 단위 | 건수는 「건」, 문서 · 기획 · 규칙은 「개」, 비율은 %(소수 없음). 값이 없으면 `-`, 0은 「0」 |
| G10 | 날짜 · 시각 | 날짜 `YYYY-MM-DD`, 시각 `YYYY-MM-DD HH:mm`. 한 화면에 두 꼴을 섞지 않는다 |
| G11 | 포털 색 | `acc`(파랑)는 링크 · 고른 메뉴 · 고른 탭 · 주 버튼 · 지금 단계에만 쓴다. 수량 · 상태에 쓰지 않는다. 맡는 곳에는 색을 쓰지 않는다. 다른 사이트로 가는 링크는 ↗, 내려받기는 버튼 |
| G12 | 문장 | 합니다체, 메뉴 · 탭 · 열 이름은 명사형, 같은 대상은 한 이름(3장). 문장 안에 긴 줄표 · 화살표를 쓰지 않는다 |
| G13 | 폭 | 본문 최대 1680px. 읽는 화면은 본문을 넓게 쓰고 오른쪽 240px에 이 페이지 목차 · 관련 정보를 둔다 |
| G14 | 출처 | 값이 모인 곳(GitHub main 커밋 · 테스트결과 엑셀 차수)을 화면 어딘가 한 번 밝힌다 |

## 3. 전역으로 정할 것

화면마다 다르게 쓰던 것이다. 2026-11-13 추천안대로 모든 화면에 먼저 반영했다(팀 확인 전). 팀이 다르게 정하면 이 표를 고치고 모든 화면을 같이 고친다.

| # | 정할 것 | 전에 | 반영한 것(Claude 판단안 · 팀 확인 전) |
| --- | --- | --- | --- |
| Q1 | 「아직 안 정한 것」을 부르는 이름 | 미결 · 미결정 · 정할 것 · 결정 필요 · 미확정이 화면마다 섞임 | 메뉴 · 묶음 이름은 「정할 것」 하나. 출처별 이름은 그대로 쓴다: 기획 「미결정」 · 품질 「결정 필요」 · 공통 정책 「미확정」 |
| Q2 | 막힌 일 이름 | 진행 필요(엑셀 시트 이름) · 막힌 검사 | 「막힌 검사」 |
| Q3 | 날짜 꼴 | 최근 반영 `11/13 10:01`, 나머지 `2026-11-12` | G10 대로 `YYYY-MM-DD HH:mm` 하나 |
| Q4 | 홈을 누가 먼저 보나 | 기획 · 개발 · QA 모두에게 같은 홈 | 그대로 하나. 맨 위 타일을 「기획이 할 일 · 개발이 할 일」 둘로 나눔 |
| Q5 | 기획 단계 이름 | 기획서 → 정의서 → 검토 → 확정 → 품질 검사 | 저장소 상태 값(draft · sample · in-review · approved)과 1:1 로 맞춤 |
| Q6 | 품질 결함 맡는 곳 | 엑셀 「담당」 칸(기획 · 개발 · 기획 → 개발 등) 그대로 | 「기획 · 개발 · 디자인」 셋으로 묶어 보이고 원래 값은 상세에 |

## 4. 화면의 목적과 쪽 패턴

부품마다 쓰는 법과 견본은 `ds/portal.css` 의 부품 절에 있다. 이 문서에는 사이트의 어느 화면이 어느 패턴을 쓰는지만 적는다.

| 목적 | 화면 | 주소 | 쪽 패턴 |
| --- | --- | --- | --- |
| 본다 | 홈 | `#/` | HomePattern: 띠 위로 숫자 타일, 단계판, 개발이 먼저 고칠 결함 · 최근 반영 |
| 본다 | 품질 현황 | `#/qa` · `#/qa/<기획>` | 숫자 타일, 차수별 판정, 열린 결함은 어디서 고치나요?, 차수별 문서 |
| 본다 | 기획 | `#/plans` | PlansPattern: 기획 카드 |
| 고른다 | 정할 것 · 품질 이슈 | `#/open/<묶음>` · `#/issues/<기획>/<종류>[/<맡는 곳>]` · `#/issue/<ID>` | ListPattern: 쪽 탭, 요약 문장, 표, 오른쪽 상세 패널 |
| 읽는다 | 공통 정책 문서 · 운영 문서 · 기획의 정의서 탭 | `#/doc/<ID>[/<규칙>]` · `#/plan/<기획>/<정의서>` | ReadingPattern: 낮은 띠 아래 본문, 오른쪽에 이 페이지 목차와 관련 정보 |
| 읽는다 | 운영 문서 목록 · 공통 정책 목록 | `#/guides` · `#/policies` | DocList: 먼저 읽을 문서와 목적별 묶음 / 영역별 표 |
| 찾는다 | ID 찾기 · 찾기 | `#/id/<ID>` · `#/search/<낱말>` | RefList: 원문 한 문장과 가리키는 곳 목록 |

- 기획 상세(`#/plan/<기획>/<탭>`)는 탭에 따라 틀이 바뀐다. 정의서 탭은 읽는 화면이고 「남은 할 일」을 옆 정보에 둔다. 「정할 것」 탭은 목록과 상세 패널, 「품질」 · 「내려받기」 탭은 내용과 「남은 할 일」 두 단이다.
- 쪽 머리(띠)는 스크롤해도 위에 고정한다(홈은 빼고). 위치 줄 맨 앞에 「← 바로 위 쪽」 버튼을 두어 이전 쪽으로 돌아간다. 위치 줄의 상위 칸은 모두 링크이고 마지막 칸은 지금 쪽이다.
- 메뉴는 왼쪽에 둔다. 영역 여섯(홈 · 기획 · 정할 것 · 품질 · 공통 정책 · 운영 문서) 아래 하위 메뉴는 접어 두고, 지금 영역과 사람이 펼친 영역만 편다. 대메뉴 오른쪽 꺾쇠로 펼치고 접으며, 펼친 상태는 브라우저가 기억한다.
- 오른쪽 상세 패널은 머리의 「넓게 보기」 단추로 화면 폭의 70%까지 넓힌다.
- 기능정의서의 기능은 카드 하나씩 보인다. 머리(ID · 분류 · 배지), 이름(18px 굵게), 설명(본문), 연결(화면 · 정책 · 요구사항 · 비고, 회색 칸)을 나눈다.
- 다른 쪽으로 넘어가는 링크는 뒤에 → 아이콘을 붙인다. 표의 행은 → 없이 누르면 그 자리(오른쪽 상세 패널)에서 열린다. 한 쪽 안의 갈래는 띠의 쪽 탭이 맡는다. 메뉴 맨 위 버튼으로 메뉴를 접고, 접은 상태는 브라우저가 기억한다.
- 본문 폭이 1000px 아래면 목차를 숨기고 관련 정보를 본문 위 한 줄로 올린다.
- 모든 표는 머리 칸 오른쪽 경계를 끌어 열 너비를 바꿀 수 있고, 두 번 누르면 처음 너비로 돌아간다. 표가 칸보다 넓어지면 표 안에서 가로로 스크롤한다.
- 문서 표의 칸 폭은 내용 길이에 맞춘다. ID만 든 칸은 좁게 고정하고 문장이 든 칸에 남는 폭을 준다. 860px 미만(휴대폰)에서는 왼쪽 메뉴를 위로 올려 영역 여섯만 한 줄로 보이고 하위 메뉴는 숨긴다.

## 5. 고칠 때

1. 2장 전역 규칙과 4장 화면 목적을 먼저 본다.
2. 포털 양식 부품으로 그린다. 없는 모양이 필요하면 포털 양식 아티팩트에 부품을 먼저 더하고, `portal.css` 에 같은 값으로 옮긴다.
3. 색 · 크기를 화면 코드에 직접 적지 않는다.
4. 로컬에서 `python3 tools/site/build.py . <출력 폴더>`로 만들어 모든 메뉴를 눌러 본다. 어두운 화면 · 휴대폰 폭도 본다.
